{% comment %} charts/templates/charts/base.html Shared layout + the site's ONE stylesheet. Plain Django templates, no build step, no JS framework -- per CLAUDE.md's Stack section. How the stylesheet is organised (top to bottom), so a later change knows where it belongs: 1. Design tokens -- every colour, size, radius in ONE place, with a dark-mode override block. Nothing further down hard-codes a colour or a font size; it refers to a token. That's what keeps pages consistent: two buttons can't drift to 0.8rem and 0.85rem when neither of them is allowed to say a number at all. 2. Base elements -- body, headings, links, tables, form controls. 3. Layout -- the top nav bar, the page container, the page header. 4. Components -- buttons, badges, alerts, filter bar, pager, tabs. These are the shared vocabulary every page is built from. 5. Page-specific styles -- only what genuinely belongs to one screen. The rule the components encode, and the reason for the 2026-10-15 pass: an ACTION is a button (enter a week, edit, fix, search, save); a link is for going to a piece of DATA (a chart name, a week, a Discogs release).
